# 查询在浏览器内执行，每个 Chart 的结果都存成快照

AI 生成的查询由成员浏览器里的 DuckDB-WASM（运行在 Web Worker 中）对 Dataset 执行，服务端从不执行 AI 生成的查询。每个 Chart 生成或字段被修改时，都把查询结果（设有行数上限）作为 Snapshot 存到服务端；查看 Conversation、Board、Share Link 时一律读快照渲染，只有提问或手动修改字段时才需要加载 DuckDB 和原始数据。选择这个方案的原因：服务端完全没有 SQL 注入面；服务端不承担计算，部署简单；发给 AI 的只有列结构和少量样本行；Viewer 和手机端查看内容时，不需要下载好几 MB 的 WASM 和整个数据文件。

## Considered Options

- **服务端运行 DuckDB**：需要常驻进程、要管理内存，所有查询都要消耗服务端算力。
- **每个 Dataset 导入成一张 Postgres 表**：AI 生成的 SQL 会在共享数据库上执行，需要只读角色和 schema 隔离，风险面大。
- **只在 Pin 时保存快照，会话里的图表每次查看都重新查询**：打开任何会话都要等 WASM 和 Parquet 加载完成，Viewer 和手机端体验很差。

## Consequences

- 快照之所以一直正确，是因为 Dataset 不可修改。如果以后允许修改 Dataset，快照就需要失效机制。
- 图表间的联动筛选需要在查看看板时重新查询，与"读快照渲染"冲突，所以推迟到 v2。
- 单个文件的大小受浏览器内存限制，因此设了上传上限。
- 会话列表先加载文字和 ChartSpec，快照数据在条目进入视口时再按需拉取（见 ADR-0007）。
